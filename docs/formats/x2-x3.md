# X2/X3 models

- **Status:** partial implementation (static frame/mesh data)
- **Loader:** `OpenSora.Common/ModelLoading/ModelLoader.cs`, `Frame.cs`, `MeshData.cs`, `MaterialData.cs`
- **Consumer:** `OpenSora.Common/ResourceLoader.cs` and `OpenSora.Viewer`
- **Fixtures:** `OpenSora.Tests/Fixtures/SyntheticModel.cs`
- **Tests:** `OpenSora.Tests/ModelFixtureTests.cs`, `OpenSora.Tests/FixtureToolkitTests.cs`

## Overview

`_X2` entries are map/field models (version 2). `_X3` entries are character models (version 3) and were
not present in the sampled FC installation. The loader supports both versions and stores a tree of
frames with meshes and materials.

Archive payloads are usually Falcom-compressed. After decompression, an X2 stream begins with a
4-byte version header and then the zero-terminated root frame ID (for example
`04 01 01 00 "Frame_SCENE_ROOT"`). X3 uses a 48-byte version header.

## Frame layout

The current parser reads:

```
uint8/bytes[version == 2 ? 4 : 48]   version header (skipped)
char[] rootId                       zero-terminated
```

For each frame:

```
char[] id                                      zero-terminated
padding                                        260 - (idLength + 1)
float transform[16]                            4x4 matrix or equivalent transform
if id == "Frame_SCENE_ROOT":
    padding                                    version == 2 ? 51 : 53
else if version == 3:
    int32 materialCount
    repeat:
        skip 70
        char[] materialName                    zero-terminated
        skip 780 - materialNameLength
        optional skip 2 between materials
uint16 childCount
repeat childCount:
    char[] childId                             zero-terminated
    if childId contains "Frame": recursive frame
    if childId contains "Mesh":  mesh
```

The 260-byte frame header includes the ID and its terminator. Root-specific padding and version-3
material records are inferred from the current parser.

## Mesh layout

After the mesh ID:

```
padding                                        264 - (idLength + 1)
int32 textureCount
repeat:
    int32 primitivesStart
    int32 primitivesCount
    int32 verticesStart
    int32 verticesCount
    version 2:
        int32 unused
        skip 164
        char[] textureName                    zero-terminated
        skip 360 - textureNameLength
    version 3:
        skip 96
        int32 materialIndex
        skip 4
        textureName = parentFrame.materials[materialIndex]
int32 vertexCount
repeat vertexCount:
    float positionX, positionY, positionZ
    float normalX, normalY, normalZ
    int32 unused0, unused1
    float u, v
int32 indexCount
repeat indexCount: int16 index
skip 44
```

Current vertex mapping converts stored Z to `-Z` and keeps X/Y. The two unused integers between
normal and UV are skipped. The 44-byte trailer is not interpreted.

## Status and limitations

- The viewer renders static meshes with textures; there is no skinning, skeletal animation, or model
  animation playback yet.
- The version-3 material path indexes `parentFrame.materials`, so nested version-3 material ownership
  matters.
- Parsing errors are logged through diagnostics; header failures are rethrown, while body failures may
  return a partial frame tree.
- Materials contain only a texture name in the current model. Lighting, blending, and shader data are
  not interpreted.

## Testing

- Synthetic X2 model: root frame, child frame, one mesh, material, three vertices, indices.
- Synthetic X3 model: root frame, child frame, one mesh, no materials.
- Fixture toolkit writes X2/X3 streams to a temp folder and loads them back.
- Real FC viewer smoke tests load X2 models.

## Open questions

2. Material records and their lighting/blending parameters.
3. Skeletal animation and skinning data location.
4. Version 2 vs version 3 differences beyond header and material records.
5. The 44-byte mesh trailer and other skipped fields.
6. X3/character-model coverage (none observed in FC).
7. SC/3rd model variants and texture mapping semantics.
